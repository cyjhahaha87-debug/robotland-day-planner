# 요청 지연 수정과 맥에서 이어하기

2026-09-29. 기존 `main`의 다국어 화면·선택형 채팅·교사 반 초대 QR까지 먼저 받아 유지했습니다.

## 지금 이어서 할 일

웹 코드는 GitHub `main`에 올리면 Netlify가 자동 배포합니다. **Google Apps Script는 별도 배포가 필요합니다.** 이번 수정은 웹과 Apps Script 양쪽에 있으므로 아래 스크립트 교체까지 해야 조회 잠금 문제가 해소됩니다.

1. 맥에서 [관리용 구글시트](https://docs.google.com/spreadsheets/d/1BPPSKOvkuQarxyLL08L3WL1i5hlqif0ORETJ_Gr2o18/edit)를 엽니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. GitHub의 [최신 RobotlandSheets.gs 전체 코드](../integration/RobotlandSheets.gs)를 엽니다. `Raw` 화면의 전체 내용을 복사해 기존 `Code.gs` 전체를 교체하고 저장합니다.
4. **배포 → 배포 관리 → 기존 웹앱의 연필 → 버전: 새 버전 → 배포**를 누릅니다.
5. 기존 웹앱 주소를 유지합니다. 새 프로젝트 생성, 처음 설정 재실행, 시트 데이터 삭제, 비밀키 변경은 필요 없습니다.
6. [저장소 상태 주소](https://script.google.com/macros/s/AKfycbxaHdQrjIJVcFoSL5KK1H5mjPrjOWRwIDllJUStdfp7Ows-UgszvY66I20jRAkNaokerA/exec)를 열어 `version`이 **`2026-09-29.1`**, `features`에 **`concurrent-reads`**가 있는지 확인합니다. 이 주소는 버전 정보만 표시합니다.
7. [공개 앱](https://robotland-trip.netlify.app/)을 새로고침합니다. 기존 교사 코드와 이름으로 입장하고 반·조·교사 모임을 확인하세요.

GitHub에 파일을 올렸다는 것과 Apps Script가 배포됐다는 것은 다릅니다. 이 문서 작성 시점에는 Apps Script 새 버전 배포를 아직 확인하지 않았습니다. 마지막으로 확인한 운영 버전은 `2026-09-28.5`입니다.

## 원인과 변경 내용

앱의 “요청이 많아요. 잠시 후 다시 시도해 주세요.”는 이용량을 조회해서 띄우는 문구가 아니었습니다. 구글시트의 모든 요청이 하나의 잠금을 기다리다 10초 안에 얻지 못했을 때 나오던 앱 자체 오류입니다. 로그인 때 여러 조회가 겹치고, 화면 복귀 때 자동 복구 등록까지 반복되어 적은 인원으로도 발생할 수 있는 구조였습니다. 실제 서비스 전체의 이용량 한도 초과를 측정한 것은 아닙니다.

- Apps Script의 로그인 상태·공지·조·교사 현황 등 10종 조회에서 공통 저장 잠금을 제거했습니다. 반 권한과 세션 검사는 매 요청 그대로 수행합니다.
- 조회하면서 학생 명단이나 알림 시트를 생성하던 처리를 분리했습니다. 학생 명단을 영구 기록하는 처리는 로그인·로그아웃 등 저장 작업에서 유지합니다.
- 같은 조회 안에서 같은 시트를 여러 번 읽으면 첫 결과를 재사용합니다. 다른 요청까지 로그인 정보나 반 데이터를 캐시하지 않습니다.
- 실제 저장은 잠금을 유지하고, 저장 내용을 확정한 다음 잠금을 해제합니다.
- 브라우저는 저장소 요청을 하나씩 보내고 같은 대기 중 조회를 합칩니다. 저장 이후 조회는 이전 조회와 합치지 않습니다.
- 반이나 사용자가 바뀌면 이전에 대기하던 요청은 보내지 않습니다.
- 저장소가 잠금을 얻지 못해 **작업을 시작하지 않았다고 명시한 경우**에만 한 번 자동 재시도합니다. 통신 시간 초과·로그인 실패·실제 이용량 제한은 자동 재전송하지 않습니다.
- 화면을 숨긴 동안 자동 조회를 멈추며, 반복 실행되던 새로고침 타이머를 하나로 유지합니다. 조회 시작 시간을 조금씩 분산합니다.
- 학생 기기의 자동 재입장 정보는 화면에 돌아올 때마다 쓰지 않고, 해당 로그인에서 성공했다면 6시간 동안 중복 등록을 생략합니다.

공지 푸시는 별도 발송 경로를 그대로 사용합니다. 앱을 닫아 자동 조회가 멈춰도, 허용해 둔 기기의 공지 푸시를 끄지는 않습니다.

구글시트 기반 저장소의 실제 처리 속도·Google 한도 자체가 없어지는 것은 아닙니다. 학교 전체 규모의 실사용 부하 검증은 별도입니다.

## 맥에서 소스 작업

이미 저장소가 있다면 저장하지 않은 변경부터 확인한 뒤 받으세요.

```sh
cd robotland-day-planner
git status
git pull --ff-only
npm ci
npm test
npm run dev
```

처음 받는다면:

```sh
git clone https://github.com/cyjhahaha87-debug/robotland-day-planner.git
cd robotland-day-planner
npm ci
npm test
npm run dev
```

Node.js 22 이상이 필요합니다. 로컬 화면은 `http://127.0.0.1:4317/`에서 엽니다. 서버 비밀키는 Git에 넣지 않았고 기존 Netlify 설정을 유지합니다. 반 기능의 실제 운영 확인은 공개 앱에서 하세요.

## 검증과 주요 파일

- `npm test`: 기존 반 구분, 재입장, 공지·푸시, 조 초대, 점심 동선, 다국어·선택형 채팅과 새 요청 제어 테스트를 실행합니다.
- `npm run build`: Netlify 배포용 파일을 생성합니다. 새 서비스 워커 캐시에 요청 제어 파일을 포함합니다.
- `tests/request-client.cjs`: 겹치는 조회 합치기, 저장 순서, 반 변경 후 대기 요청 취소, 안전한 재시도만 한 번 수행하는지 검증합니다.
- `tests/read-concurrency.cjs`: 저장 잠금이 사용 중이어도 10종 조회가 완료되고 시트를 바꾸지 않는지, 권한 검사와 이전 학생 명단 보존이 유지되는지 검증합니다.
- `public/request-client.js`: 요청 순서·중복 제거·재시도 담당.
- `public/classroom.js`, `public/groups.js`, `public/staff.js`, `public/push.js`: 자동 조회 및 복구 등록 담당.
- `integration/RobotlandSheets.gs`: 운영 Apps Script로 복사할 전체 코드.

맥에서 새 대화를 열면 “`docs/요청지연-수정과-맥-인계.md`를 읽고 Apps Script 2026-09-29.1 배포 상태부터 확인해 줘”라고 요청하면 이어서 점검할 수 있습니다.
